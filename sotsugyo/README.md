■サービス概要
増え続ける「後で読む」技術記事を放置させず、「何を学ぶか」の目的意識を持って消化するための学習管理サービスです。 
単なるブックマークではなく、読了予想時間の設定や、読後のアウトプット（メモ・実装完了）をセットで行うことで、
技術の定着をサポートします。

■このサービスへの思い・作りたい理由
プログラミング学習を始めてから、QiitaやZenn、公式ドキュメントなど、
有用な記事をとりあえずブックマークする習慣がつきました。
しかし、気づけば「積読」が100件を超え、どこから手をつければいいか分からなくなったり、
読んだだけで満足して技術が身についていなかったりすることに強い課題を感じました。
 「ただ読む」から「技術を習得する」ためのステップを仕組み化したいと思い、このサービスを企画しました。

■ユーザー層について
メインユーザー： プログラミング初学者〜中級者
理由： 覚えるべき技術が多岐にわたり、情報の取捨選択や学習管理に苦労している層が最も多いと考えたため。

■サービスの利用イメージ
ユーザーは読みたい記事のURLを登録します。
その際、「この記事で何を知りたいか（例：Railsのバリデーションの書き方）」をメモし、優先度を設定します。
 週末などまとまった時間に、ダッシュボードから「今週読むべき記事」を確認し、
 読み終えたら学んだ内容を3行程度の要約（または実装コードのリンク）と共に記録します。
 これにより、**「積読が減る快感」と「成長の実感」**を同時に得られます。

■ユーザーの獲得について
X (Twitter): #RUNTEQ や #プログラミング学習 などのハッシュタグで、学習進捗を共有したい層にアピールします。
Qiita/Zenn: 自ら記事を執筆し、その記事の活用例としてサービスを紹介します。

■サービスの差別化ポイント・推しポイント
差別化: PocketやNotionなどの既存ツールは「保存」がメインですが、本サービスは**「消化（アウトプット）」**に特化しています。
推しポイント: 記事のOGP画像（アイキャッチ）をカード形式で表示し、視覚的に「読みたい！」というモチベーションを維持します。また、読み終えた記事の数や学習時間をグラフ化し、自分の頑張りを可視化します。

■機能候補
MVPリリース時
　ユーザー登録・ログイン機能
　記事URL登録機能（OGP取得によるタイトル・画像自動表示）
　学習ステータス管理（未読・読書中・完了）
　「この記事で学びたいこと」メモ機能
　一覧表示・削除・検索機能

本リリース時
　学習時間の可視化グラフ（Chart.jsなど）
　優先度（高・中・低）による並び替え
　Chrome拡張機能（閲覧中のページを即座に登録）
　SNSシェア機能（「今週は〇件の記事を消化しました！」）

■使用する技術スタック
フレームワーク: Ruby on Rails 7 (Ruby 3.2)
データベース: PostgreSQL
デプロイ先: Render または Railway

■使用予定のライブラリ:
setomits/opengraph_parser: URLからOGP情報（タイトル、画像）を取得するために使用。
Chart.js: 学習データのグラフ化に使用。
Tailwind CSS: UIデザインを効率的に整えるために使用。
